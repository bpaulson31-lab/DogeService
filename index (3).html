DogeService is an original profile and data module for Roblox games. Store player progress, manage inventory, read profile values, and keep saved data under server control.

Get started →Read documentation ↗

No build step · Uses Roblox DataStoreService · Client API is read-only

💾

Persistent profiles

DataStore-backed player records with autosaving and session leases.

🎒

Inventory & stats

Convenient methods for currency, nested data paths, and item stacks.

Server-authoritative

Clients can read snapshots and updates, but cannot write saved data directly.

01 / Quick start

Three scripts. One API.

Place each source file in the matching Roblox Studio location. DogeService creates its remotes and begins loading data through the bootstrap.

1

Public ModuleScript

ReplicatedStorage / DogeService
Paste DogeService.luau.

2

Server ModuleScript

ServerScriptService / DogeServiceServer
Paste DogeServiceServer.luau.

3

Bootstrap Script

ServerScriptService / DogeServiceBootstrap
Paste DogeServiceBootstrap.server.luau.

Server exampleLuau
local RS = game:GetService("ReplicatedStorage")
local DogeService = require(RS:WaitForChild("DogeService"))

local function reward(player)
    local profile, err = DogeService:WaitForProfile(player, 20)
    if not profile then
        warn("Profile not ready:", err)
        return
    end

    profile:Increment("Currency.Coins", 100)
    profile:AddItem("Potion", 2)

    print(profile.Name, profile.UserId)
    print(profile:Get("Currency.Coins", 0))
end
DataStore setup: Publish a separate test experience and enable Game Settings → Security → Enable Studio Access to API Services there. Avoid testing against live player data.
02 / Client & server

One module name. Different permissions.

Require the public DogeService ModuleScript from either side. On the server it routes to the full implementation; on the client it exposes a read-only profile snapshot.

Client read exampleRead only
local RS = game:GetService("ReplicatedStorage")
local DogeService = require(RS:WaitForChild("DogeService"))

local profile, err = DogeService:WaitForProfile(20)
if not profile then
    warn(err)
    return
end

local coins = DogeService:GetValue("Currency.Coins", 0)
local inventory = DogeService:GetInventory()
print(profile.Name, coins, inventory)

DogeService.ProfileUpdated:Connect(function(snapshot)
    if snapshot then
        print("Updated:", snapshot.Data.Currency.Coins)
    end
end)

03 / API overview

The calls you'll use most.

Path strings make nested values easy to reach. Mutations return a success boolean plus a result or an error message.

Server callWhat it does
:GetProfile(player)Returns the active server profile, or nil.
:WaitForProfile(player, timeout)Waits for the player's profile to finish loading.
profile:Get(path, default)Reads a nested value such as Currency.Coins.
profile:Set(path, value)Validates and changes a value.
profile:Increment(path, amount)Increments a numeric value.
profile:AddItem(id, quantity)Adds an item to an inventory stack.
profile:RemoveItem(id, quantity)Removes available inventory quantity.
profile:HasItem(id, quantity)Checks if the inventory has enough of an item.
profile:Save()Requests an immediate save.
profile:Sync()Publishes direct server data changes to the client snapshot.

04 / Important

Never trust the client with saved data.

🔐

Server is the source of truth.

DogeService intentionally rejects client-side write calls. For purchases, rewards, trades, or upgrades, use a game-specific RemoteEvent/RemoteFunction, validate the request on the server, then change the profile server-side.

  • Never let clients submit arbitrary profile paths or user IDs.
  • Validate currency, ownership, costs, cooldowns, and game rules before any change.
  • Use a separate test experience for DataStore testing.

Honest status: this is a starter implementation, not a battle-tested replacement for ProfileStore. Test join/leave, reconnects, concurrent sessions, throttling, schema changes, and shutdown saves before production use.
